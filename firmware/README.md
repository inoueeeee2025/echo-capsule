# firmware — カセット型デバイスのファームウェア

**このディレクトリが正（source of truth）です。**
ファームウェアを直すときは、必ずここのファイルを編集してから実機に書き込んでください。

手元のスケッチブックや個人のフォルダにコピーを置いて編集すると、
アプリ側の修正と対応が取れなくなります。

---

## なぜアプリと同じリポジトリに置くのか

ボタン入力はデバイスとアプリの**両方に実装がある**ため、片方だけ直しても直らないバグが存在します。

実例：「REC を離しても録音が止まらない」は、以下の2つが独立に同じ症状を引き起こします。

- ファーム側 `F-1` — レート制限で「離した」の送信が欠落する
- アプリ側 `B-2` — 録音開始処理の完了前に離すと停止処理がスキップされる

同じリポジトリに置くことで、「この修正とこの修正はセット」という関係がコミット単位で残ります。

## 書き込み手順

**書き込むまで、コードを直してもデバイスの動作は一切変わりません。**

1. Arduino IDE で `echo_capsule_controller/echo_capsule_controller.ino` を開く
   （Arduino IDE 2 は任意のフォルダの `.ino` を開けます）
2. ボードとポートを選択する
3. 検証（✓）でコンパイルが通ることを確認
4. 書き込み（→）
5. シリアルモニタ（**115200 baud**）を開き、`[WiFi] AP IP=192.168.46.1` が出ることを確認
6. スマホを `_echocapsule_dev` に接続し、アプリの `/dev` 画面で `connected` になることを確認
7. STOP / PLAY / REC を押して、`/dev` 画面の表示が切り替わることを確認

## 変更後に実機で確認すること

ファームを直したら、最低限これだけは通してください。
いずれも過去に見つかったバグの再発チェックです。

- [ ] REC と PLAY を 50ms 以内に連続で押しても、両方アプリに届く
- [ ] REC を素早く押して離しても、アプリ側の録音が止まる
- [ ] アプリを何度も再接続させても、数十分後まで安定して動く
- [ ] WebSocket 未接続の状態で REC を押すと赤 LED が点く
- [ ] スマホの Wi-Fi を切ると、数秒以内に緑 LED が消える
